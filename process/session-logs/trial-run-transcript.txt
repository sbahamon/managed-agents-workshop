⏺ state.sync is a small cache in lab/state.py:

  def sync(key: str, create: Callable[[], str]) -> str:
      existing = get(key)          # already have an id for this key (for your 
  handle)?
      if existing:
          return existing          # reuse it and skip create()
      new_id = create()            # otherwise call create() once
      put(key, new_id)             # save the id in .ma201-state.json
      return new_id

  There are two things to get right.

  1. Pass a function, not a result. sync only calls create when nothing is
  cached. If you call the API yourself and hand sync the result, the API call
  has already happened before sync runs, and every run creates a new environment
  anyway. That's why the docstring says lambda: .... A lambda delays the call
  until sync decides it's needed.

  2. Look at the type hint: Callable[[], str]. Your function has to return an id
  string. The create call returns an environment object. What do you need to
  take from that object so the function returns what sync caches?

  Here's the general pattern, with placeholders:

  return state.sync("some_key", lambda: <make the thing>.<the part sync wants to
  store>)

  The docs section linked in the docstring shows what goes in <make the thing>:
  the create call, plus the name, config and metadata the docstring lists.

  To check it worked, run --step 1 twice. Both runs should print the same
  environment id. If the second run prints a new id, look again at point 1.
